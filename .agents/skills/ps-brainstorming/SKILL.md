# Brainstorming

Do not begin implementation until the direction is sufficiently understood. Match the depth of discovery to the scope and risk; use the lightest process that produces a sound decision.

## Workflow

1. Establish the outcome: problem, users, expected result, constraints, and existing context. Ask only questions whose answers materially affect the decision, preferably one at a time.
2. Inspect the existing product and code patterns before proposing new systems or abstractions.
3. Classify scope:
   - Small: a focused adjustment; keep the process brief.
   - Medium: a module, workflow, or integration; define data flow, screens, dependencies, and risks.
   - Large: a product or major shift; define milestones and explicit decisions.
4. When trade-offs matter, compare a simple, balanced, and advanced option. Recommend the simplest option that fits, including its trade-off.
5. Present the proposed objective, user flow, components, data model, UI structure, risks, and scope boundaries. Get confirmation for long-term architectural, database, or major UX decisions.

## Decision record

For meaningful choices, state: decision, reason, alternative considered, and trade-off. Reuse existing components and patterns before creating new ones. Keep the agreed scope during delivery.
