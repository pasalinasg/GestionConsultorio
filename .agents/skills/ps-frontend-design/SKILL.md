# Frontend design

Ground the design in a concrete product subject, audience, and single page/job outcome. Derive visual choices from that context rather than default trends.

## Work in two passes

1. Create a compact design plan: a named palette of 4-6 hex colors, type roles (display, body, utility as needed), layout concept with a simple ASCII wireframe when useful, and one signature element the experience will be remembered by.
2. Critique the plan against the brief. Replace any choice that could have been made for any unrelated product; explain the product-specific reason for the revision. Then implement the approved direction faithfully.

## Principles

- Let hierarchy and structure communicate real meaning; avoid decorative patterns that do not fit the content.
- Make typography, copy, spacing, color, and interaction deliberate. Prefer specific plain-language labels and consistent action names.
- Spend boldness on one justified signature; keep surrounding elements disciplined.
- Use motion only where it serves the experience. Respect responsive layouts, keyboard focus, and reduced-motion preferences.
- Check rendered results when possible and correct visual issues, including CSS specificity conflicts.

Before delivery, ensure the page feels specific to the product, not generated from a stock layout.
